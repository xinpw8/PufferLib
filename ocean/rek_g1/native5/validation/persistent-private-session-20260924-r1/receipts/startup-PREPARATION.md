# Private startup menu variant

Built and CPU-tested only. No installation, game connection, UI interaction, process signal, GPU work or controller launch was performed by this stage.

The previous driver allowed `Intro` only as a passive wait state within its 45-second entry deadline. `ConfirmLoggedIn` accepted only `Login`. There was no native Skip command. The new driver requests `SkipIntro` only when state reports the isolated Spark surface and an active intro with a visibly shown, enabled native Skip control. The bridge rechecks those facts, requires the existing exclusive lease and invokes `IntroScreenController.OnSkipClicked()`. Native completion stops video/timer playback and follows the existing deferred login/home route; authentication is untouched.

`ExitUnsupportedPrivateAiPairing` is separate from both old exit commands. Existing Spark isolation and exclusive-lease guards remain. It requires no active policy/control, proven private unranked Bot1 with no human occupant, exact local G1 and opponent T800 semantics and bone signatures, matching slots and client-visual fighters. The native menu is opened if needed, then its normal Home-exit callback is invoked. Active matches may show the native Forfeit pane. Confirmation uses its native button callback only after an observed Home target, open Forfeit pane and visibly shown, enabled button, with the same scope revalidated. No direct field writes, synthetic keys, process termination or human/public-session exit is provided.

Startup recovery only runs for a previously observed unsupported pair after acquiring the lease. It polls for normal Lobby/Home for at most 15 seconds. Missing confirmation or missing Home stops that attempt and leaves the client running. A newly encountered unsupported pair remains an excluded attempt under the existing exact-pair guard. Existing fairness, scoring, inference, action stream, watchdog, timing, masks and policy settings are unchanged. Both new commands remain unavailable on the Windows execution surface.

Native behavior was checked in existing private recovered files under `C:\rekagent\work\controller-audit-isil\IsilDump\REKApp\REKApp`: `IntroScreenController.txt`, `LobbyShellController.txt`, `GameMenuController.txt`, `GameMenuView.txt`. `OnSkipClicked` calls `FireFinished`; `HandleExitHomeRequested` uses the normal exit-screen selection and may show a confirmation; `OnForfeitConfirmInternal` invokes the normal forfeit event; `ExitToLobby` stops the network session and loads the lobby scene. Recovered game bodies are not copied into this stage.

Artifacts and source pins are recorded in `BUILD-RECEIPT.json`. New config shape is unchanged: use the new driver, replace the relay executable path, and replace the relay's final expected-bridge-SHA argument. Bridge version remains 0.4.9; exact DLL SHA is the identity binding.

Executed checks: `node --test startup.test.cjs` passed eight tests; `dotnet run --project tests/StartupMenuTests.csproj -c Release` passed 30 guards. Final bridge build and self-contained relay publication succeeded. These checks do not establish that a real native Skip or exit has completed; root must verify those transitions during the planned isolated maintenance test.
