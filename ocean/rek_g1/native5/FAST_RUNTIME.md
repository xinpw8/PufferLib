# Compact action-level CUDA candidate

`fast_runtime.cu` implements the existing native runtime API in a separate
binary. It requires `REK_PHYSICS_BACKEND=semantic_cuda`. The existing
MuJoCo/Puffysics runtime remains unchanged. Policies for this candidate must
have a separate configuration identity from full-physics policies.

The 17 September primitive-contact experiment adds opt-in
`REK_FAST_GEOMETRY=primitive_samples_v1` and
`REK_FAST_CONTACT_SUBSTEPS=1..16` (default 4 when selected). It retains the
12 individual authored striker shapes and three target shapes, with exact
static narrowphase and sampled rigid-pose interpolation. The legacy enclosing
sphere mode remains the default. This is separate from the scoring selection;
the experiment uses `recovered_hit_rules_v2`, `recovered_bot1_v1` and
`rendered_pose_v1`. Current measurements, limitations and checkpoint identity
are in [the experiment report](validation/human-contact-20260917/RESULTS.md).
The historical version-specific results below do not describe that new mode.

## What runs

Each step advances 0.02 simulated seconds. One CUDA warp owns an arena with
two fighters. Lane 0 advances both action schedulers, slider motion, symmetric
body separation, swept strike/target contacts, points and timed round
outcomes. All lanes write poses, observations and masks cooperatively. The
entire step is one CUDA kernel. There are no per-step allocations, host reads,
CPU physics calls, sorting passes, joint solves, or controller-network calls.
Reset is one kernel. The existing native PufferLib learner captures policy
inference plus this step over a rollout horizon.

The immutable asset loader reads the existing model and motion files and
bakes forward kinematics before training. Its pose, effector and target
arrays are uploaded once. It does not integrate CPU dynamics. The exact
manifest/model hashes and approximation parameters are printed at startup.
All state evolution during training and evaluation occurs in CUDA. Inspection
and logging explicitly copy results at their existing reporting boundaries.

## Retained information

- Existing 223-observation, 33-action interface and model-order 72-qpos,
  70-qvel rendering interface.
- Existing category order: continue; neutral; forward/back/left/right;
  yaw left/right; eight translation/yaw combinations; 17 discrete moves.
- Existing 24 route identities, prerecorded joint/root poses, configured
  traversal durations and native action-to-route mapping.
- Six baked strike primitives, including both knees, and three target
  primitives from the actual model geometry.
- An attack started over held yaw owns movement until completion; desired
  yaw can be changed or released meanwhile and resumes afterward.
- Translation must settle before starting an attack. Attacks entered while
  translating are discarded. During an attack, other attacks and translation
  inputs are discarded. There is no stacked move queue. Neutral and yaw
  updates only alter desired held yaw during an active attack.
- Masks open at the configured completion boundary. The final strike sweep
  still runs on the final action tick.

## Explicit approximations

This is a reduced-order simulator, not a demonstrated REK parity result.
Recorded motion root XY is effectively stationary. Therefore root translation
is generated by an explicitly chosen planar motion model. Root orientation
follows the clip. Physical knockdowns are not modeled in version 3. There is no articulated inertia,
balance-controller inference, friction solver, general contact solver or
integrated joint state. Rendering and hit trajectories use prerecorded poses.
Version 1's polar-bearing feature uses the slider's logical heading. The
full-physics encoder projects the actual root quaternion instead; they can
differ while a clip turns the torso/root. This is another reason to keep
candidate policies and configuration identities separate.

The candidate uses conservative bounding spheres from the asset bake and
relative swept-sphere tests over each 20 ms interval. It does not reproduce
native collision manifolds, hit-apex classification, recoil or full referee
logic. Per-effector contact must separate before another hit, and successful
hits have a 10-tick per-effector cooldown. A hit is one point. Hits do not
declare a physical fall, award synthetic knockout points, or reset either
fighter's position. Version 3 rounds end on the configured timer and are
decided by points. Physical knockdown scoring remains an unimplemented
requirement for authentic REK parity.

Configuration defaults, printed with every run:

| Variable | Default | Meaning |
| --- | ---: | --- |
| `REK_FAST_MOVE_SPEED` | 1 m/s | Planar translation target |
| `REK_FAST_YAW_SPEED` | 1.8 rad/s | Held-yaw target |
| `REK_FAST_BODY_RADIUS` | 0.22 m | Slider separation radius |
| `REK_FAST_HIT_SPEED` | 0.35 m/s | Minimum effector speed to score |

Legacy `REK_FAST_DOWN_DAMAGE` settings are explicitly ignored with a startup
diagnostic in version 3. They cannot re-enable the removed teleport trigger.

Braking, yaw ramp and settling thresholds come from the loaded semantic
configuration. Transferring them to slider dynamics is itself a model choice.
Round duration uses the existing configuration, with 120 seconds if omitted.

The scripted opponent approaches until 1.05 m, retreats below 0.55 m, aligns
within 0.16 rad and cycles through 16 attacks. The emote is excluded. These
are candidate-opponent settings. Both sides can use exactly this GPU policy.
For this backend only, external override value `2` selects this GPU script;
`0` preserves the normal action source and `1` selects the external action.
The full-physics runtime retains its existing override behavior.

## Version 2 episode observation contract

Each training episode is one independent round, lasting the configured time
(20 seconds in the benchmark). Version 2 could also end on its synthetic
knockdown limit; version 3 removes that unsupported rule.
Observation 186 is therefore always episode-local round 1. The cumulative
session counter remains available in `RekNative5RoundResult.round_number`
for UI and diagnostics. It does not enter raw, encoded or learner policy
observations. This changes no movement, hit, scoring, timing or reset rule.

Version 1 incorrectly exposed that cumulative counter to the policy. The
same frozen BF16 checkpoint won 294/512 matches (57.42%) with this input held
at 1 and 510/512 (99.609%) with it held at 64. Both diagnostics used the same
sampled policy seed, opponent, 128 arenas, two rounds and both fighter sides.
Those interventions establish dependence on a training-session artifact;
the high late-training win rate did not establish strong fresh-session play.
These diagnostic overrides are not production evaluation settings. Version 2
requires a fresh training run and independently evaluated checkpoints.
Version 1 compiled artifacts and results remain preserved separately.
The same GPU regression fails against preserved version 1 objects and passes
against version 2: observation 186 stays 1 across three independent 20-second
rounds while diagnostic round numbers advance. The full input/contact
regression also retains its previous outcomes. Evidence is under
`validation/semantic-fast-20260914/episode-observation/`.

## Validation boundary

Compilation has succeeded for the actual Spark `sm_121` target. The first
compiled step kernel used 72 registers and had zero register spills. Those
compiler reports are not a training-speed or correctness measurement.
The independent input/contact probe passed against `build-v1`: desired yaw
pause/resume and replacement/release, discarded stacked inputs, exact 157-tick
completion, translation settling, and two bitwise-identical 6,400-tick contact
replays with actual points and knockdowns. Evidence is under
`validation/semantic-fast-20260914/input-probe/`.

A native 512-arena training trace verified exactly one fused environment
kernel per learner action batch. The measured post-first-epoch interval
contains 1,040,384 transitions in 0.542016256 seconds, approximately 1.92 million
profiled training SPS. This is a short instrumented measurement, not maximum
throughput. Its environment kernel share is 15.324%; PPO is 57.125% and learner
inference/rollout I/O is 27.549% of summed kernel time. Full evidence and
denominators are under `validation/semantic-fast-20260914/profile/`.

Human evaluation must use this same runtime implementation. These results
establish the candidate's tested behavior and execution costs, not authentic
gameplay parity or a superhuman policy.

## Version 3 position-reset correction

Version 2 accumulated arbitrary hit damage and treated a threshold as a fall.
At a 0.64 m separation, two separately entered side kicks each produced one
hit. The second raised the defender's fall count and added five extra points;
25 ticks later, both fighters returned to spawn. The standing attacker moved
1.16 m instantaneously. No physical fall was measured. The old binaries and
their training results are retained as version 2 evidence.

Version 3 removes this damage-triggered reset and its bonus points. Timed-round
and explicit operator resets remain. All 17 no-contact attack-completion probes
already preserved root XY in version 2, so this correction does not change
attack durations, movement, hit geometry or clip playback. Abrupt unblended
pose transitions remain a separate known limitation. Version 2 checkpoint
strength results do not transfer to this changed scoring/termination contract.
