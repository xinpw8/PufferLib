# Offline official-mesh proof

The installed REK G1 and octagon meshes can render the existing native pose without changing its body or joint placement. This is a saved agent smoke pose, not a human gameplay pose or a physics-parity result. The live evaluator and all game services were untouched.

![Official G1 mesh reuse, illustrative diagnostic lighting and arena cutaway](saved-pose-diagnostic-light.png)

The final reusable export is `export-r3/`: 93 mesh instances consisting of 34 robot visual instances mapped to 30 native link names and 59 arena instances, with nine original material records. Robot instances are shared by both fighters. The original prefab's active Chappie head variant is retained. The user's current cosmetic selection is unknown.

`export_visuals.py` reads the installed `sharedassets0.assets` G1 prefab Transform1650 and level1 octagon Transform1601. It retains each intervening mesh-to-link translation, rotation and scale. Vertices are transformed in the Unity basis before the independently validated Y/Z swap into the native basis; triangle winding is reversed for that reflection. Mapping, original material values, path IDs, source hashes and output hashes are in `export-r3/MAPPING.json`. For raw received bones, the same mapped local mesh vertices can be placed using the converted corresponding bone-world transform; this proof itself uses qpos and MuJoCo kinematics.

The presentation XML preserves the original 72-qpos/70-qvel, 63-body, 60-joint hierarchy and joint index mapping. It adds visual-only, noncolliding, zero-mass mesh geoms while hiding the primitive geoms. Mesh inertia is set to shell because some arena sheets have no useful solid volume. No simulation step is executed. `render_saved.cpp` independently loads the original and presentation models, checks body/joint identity and hierarchy, evaluates the same saved pose, and rejects discrepancies above 1e-12. Actual maximum body-position and quaternion-component differences were both exactly zero. See each successful render's `run.stderr` receipt.

The pose is the exact `final_qpos` field from the already closed manual-evaluator `smoke-r2/RESULT.json`, pinned by hash in the mapping. No live state or commands were requested.

The first full-arena preview was occluded by the near wall. `presentation.cutaway.xml` and `presentation.diagnostic-light.xml` explicitly hide 58 arena wall/fixture mesh instances while retaining the official floor. The complete arena remains in `presentation.xml`. The final camera is an illustrative 130-degree azimuth, 15-degree downward asset-inspection view, not the game's camera. The diagnostic image adds strong neutral headlight and gray background; the original underlit image is preserved.

Material reproduction is incomplete: the selected diffuse texture is reused with a basic MuJoCo material, while Unity custom shaders, emission, normal/roughness maps, material-property blocks, baked lighting and team coloration are not reproduced. Sixteen arena meshes have two submesh materials; this proof uses their first material for all faces. The final scoped export has no texture-decode failures. The octagon floor remains dark because its custom shader appearance is not reproduced. The exported level1 arena has not been independently certified as the user's runtime-selected scene. These limits make this an asset/mapping proof, not a ready live-viewer replacement or visual-parity claim.

Recovered `RobotFollowCamera` code contains follow/ringside modes and constructor defaults of 3 m behind, 1 m height offset and 10-degree downward tilt. Actual scene overrides, active camera mode and FOV are unverified. That camera evidence was inspected separately and was not silently substituted into the proof.

Preserved unsuccessful work: export-r1 failed on an unrelated arena scenery texture decoder; its original exporter is `export_visuals.r1.py`. Export-r2 included broader store scenery and failed MuJoCo mesh-volume loading; `export_visuals.r2.py` and `render-r1/run.stderr` preserve that stage. The final export narrows arena selection to octagon objects and uses shell inertia. An initial PNG decoding wrapper failed because MuJoCo emitted a warning before base64; the renderer itself exited 0. Subsequent wrappers select the PNG line explicitly. Successful rendering still reports an OpenGL 0x502 context warning; inspected PNGs are present, but this graphics warning is unresolved.

For reproduction on Spark, invoke `export_visuals.py --data <installed REK_Data> --model <original model.two_fighter_arena.xml> --pose <closed smoke RESULT.json> --out <new directory>` using the existing g1-extractor-venv Python. Compile `render_saved.cpp` with the exact command in `render-r1/build-command.json`, then run `render_saved <presentation.xml> <saved-qpos.f32> <original.xml>`. The binary emits its kinematic receipt on stderr and PNG base64 on stdout, after any graphics warnings. The executable performs no physics stepping or game communication.
